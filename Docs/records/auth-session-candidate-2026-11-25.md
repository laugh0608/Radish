## 登录与 Auth 重建

- Gateway 仅发布 `127.0.0.1:35443`。Auth 在 Compose 网络内通过 `web-session.test:35443` 访问同一 HTTPS 入口。测试浏览器仅在独立进程内设置域名解析、代理例外及本次 TLS 公钥信任。
- 开关关闭时，状态接口返回 `404 / legacy`。PC `1920×1080` 与移动浏览器 `390×844 @ DPR 3` 各自使用旧正式 Frontend 建立 `radish-client` 会话。重开后分别位于 `/messages` 与 `/me`，受保护账号接口均返回同一测试账号，两端均有旧版持久凭据。
- 在本项目启用候选后，匿名状态返回 `401 / cookie`。独立 PC 资料在 20:54:57 经 `radish-web` 登录，服务端回调返回 `302`，状态、取 token 及受保护账号接口均返回 `200`。浏览器会话 Cookie 具备 `HttpOnly / Secure / SameSite=Lax / Path=/`，旧版持久凭据不存在。
- 强制重建 Auth 后容器 ID 已变化，Web 密钥文件摘要一致。20:56:37 用重建前的浏览器资料恢复，状态、取 token、账号读取均返回 `200`，未出现第二次登录。该检查发生于原短令牌到期前。
- 原短令牌于 20:59:57 自然到期。21:00:20 再次重开同一资料，取 token 和读账号均返回 `200`。库中同一会话版本由 2 增至 4，短令牌截止移至 21:05:20。此时 `radish-web` 只有这一个会话，refresh token 由原先 1 条有效变为 1 条已兑换、1 条有效，确认重建后的 Auth 完成了实际轮换。
- 两个旧版浏览器分别在 21:00:42、21:00:52 完成一次交互登录，经候选回调返回原有的消息页和个人页。两个受保护账号响应均为 `200`，两端均取得新会话 Cookie，原 access / refresh 持久项均已清除。

## 通知、聊天与评论

两种视图分别用真实页面打开同一个公共频道和一篇隔离测试帖子。首轮系统 Chrome 在到期前退出，只取得初次连接。使用 Playwright 配套 Chromium 重测，移动端显式进入该频道。PC 的原 JWT 在 21:14:12 到期，移动端在 21:14:23 到期。浏览器记录的原 WebSocket 关闭时刻距各自 JWT 截止约 0.16 秒。

两端的三个 Hub 都使用了到期更晚的 JWT 完成新握手。通知页头重新读取收件箱摘要并返回 `200`；聊天和评论分别在新连接上收到加入原频道、原帖子的成功确认。测试过程中服务端及浏览器时钟均按实际时间前进。

## 主动退出

| 观察项 | PC | 移动端 |
| --- | --- | --- |
| Web 会话撤销 | `POST /web/session/logout` 返回 `200` | 同左 |
| 页面后续导航 | `/activity` 返回 `401`，退出返回成功后，受保护页又发起登录，最终进入登录表单 | 收到退出成功响应，随后 `GET /connect/endsession` 返回 `400` |
| 再查原浏览器 | 会话 Cookie 已清除，`GET /status` 和 `POST /token` 均返回 `401` | 同左 |

数据库确认对应的两个会话均已记录撤销时间、清空加密凭据，两个对应的 OpenIddict 授权均为 `revoked`。退出回流门禁仍未通过。

Auth 对 `radish-web` 登记的登出返回地址为 `https://web-session.test:35443`，退出响应使用了带结尾斜杠的地址。对该隔离端点分别提交这两种地址，带斜杠时为 `400 invalid_request / ID2052`，使用登记原值则为 `302` 并返回站内根路径。另需修正退出期间受保护页面再次触发登录的竞态，回归时覆盖并发活动响应与跨标签退出。

### 修复与定向回归

本地修复提交为 `0cf4e7f1`。Auth 已改为按登记原文生成 `post_logout_redirect_uri`。普通 Web 发起退出后由退出流程持有当前页导航权，直到浏览器离开；期间拒绝新登录，丢弃退出前已发起的登录响应。暂时退出失败后可重试，其他标签页继续清理凭据。

63 个 Auth、会话持久化及 Hub 后端定向测试通过，Client 与共享 HTTP 的 657 个测试通过。Client 构建和变更文件 Lint 通过。新增用例比对登记地址与实际退出响应，覆盖退出过程中及收到成功响应后的自动登录、迟到的活动 `401`、迟到的登录响应和跨标签状态清理。**修复版本仍待真实浏览器复验**。

## 隔夜样本

两份独立 Chrome 资料登出后重新交互登录，用受保护接口建立各自的账号和租户基准，随后关闭整个测试浏览器。次日晚在同一候选 `520c8bbf` 上首次重开各自的资料，直接访问原页面。下表的间隔从浏览器关闭算至重开后首个会话状态响应，取整至秒。

| --- | --- | --- | --- | --- |

| 移动，390×844，DPR 3 | `/me` | 21:16:28.328 | 19:51:16.989 | 22 小时 34 分 49 秒 |

**两端均通过 12–24 小时隔夜重开验收。** 两端的 `GET /web/session/status`、`POST /web/session/token` 和 `GET /api/v1/User/GetUserByHttpContext` 均返回 `200`。受保护接口返回的用户 ID 和租户 ID 与各自关页前一致。重开期间均未进入登录、授权或回调流程。会话 Cookie 保有 `HttpOnly / Secure / SameSite=Lax / Path=/`，浏览器 localStorage 中旧版 access / refresh 凭据均为空。

重开前，PC 和移动端原短令牌已分别于 11 月 25 日 21:21:18、21:21:27 到期。重开后，两条原会话的版本均从 2 增至 4，新短令牌分别在 11 月 26 日 19:56:08、19:56:17 到期。每份授权各有一条已兑换和一条有效的 refresh token。两条会话的最后活动时间均停留在前一晚的登录时刻，本次自动恢复未延长空闲期限。

两份测试浏览器关闭后，已清理本轮 6 个容器、4 个卷、项目网络和 5 个候选镜像标签。按项目标签复查，容器、卷和网络均为零，宿主端口 `127.0.0.1:35443` 已释放，含测试证书与两份浏览器资料的临时目录已删除。
