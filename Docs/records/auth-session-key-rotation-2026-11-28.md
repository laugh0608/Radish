# 普通 Web 会话专用密钥轮换验收

2026-11-28 在 OrbStack 隔离候选 `ff501159` 上通过验收。保留旧密钥和旧保护证书后，PC 和移动视口均在原短令牌到期后恢复原账号。服务端使用新密钥保存续期结果，两端再次重开时均可读取。两份样本使用不同的种子账号、独立的 Chromium 153 浏览器上下文和同一个公共租户，以轮换前后的受保护接口 `GetUserByHttpContext` 响应比对用户与租户。[会话验收矩阵](../features/auth-session-overnight-recovery-plan.md#修复验收)

## 轮换与旧会话

1. 两端登录后关闭业务页面，保留各自的浏览器上下文和 Cookie。PostgreSQL 中有两条已激活的会话，两条凭据的 Data Protection 密钥标识均指向 Web 专用卷中唯一的旧密钥。
2. 在候选 Auth 配置中将 `KeyCertificate` 切换到新证书，把旧证书保留在 `PreviousKeyCertificates[0]`。一次性维护进程使用相同的 Web 专用卷、证书和应用名 `Radish.WebSession`，通过 `IKeyManager.CreateNewKey` 生成立即生效的新密钥。
3. 密钥环中出现两个不同的密钥标识。逐个比对加密描述符内的公开证书指纹，旧密钥仍由旧证书保护，新密钥由新证书保护。旧密钥文件的 SHA-256 与轮换前一致。
4. 仅重建 Auth 容器。重新就绪后，两条原会话的绑定、凭据密钥标识、版本和短令牌截止时刻仍与基准相同。等待两个短令牌自然到期，再用各自上下文打开新的业务页面。浏览器、Auth 和数据库均使用实际时钟。

两端的 `/web/session/status`、`/web/session/token` 和受保护账号接口均返回 `200`。恢复期间，登录、授权、登录表单和回调请求均为零。数据库仍只有原来的两条活动会话，各自的会话、授权和 Cookie 绑定一致。两条会话的版本均由 2 增至 4，持久化凭据的密钥标识均由旧变新。按原授权分别核对，每个账号各有一枚已兑换和一枚有效的 refresh token。

13:24:32 两端再次关闭后重开业务页面，三个接口再次返回 `200`，账号、租户和路径与各自基准一致。会话版本仍为 4，短令牌截止未再变化，确认从新密钥保护的凭据恢复时复用了本次续期结果。
