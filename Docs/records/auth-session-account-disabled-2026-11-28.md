# 普通 Web 账号停用后的续期与会话撤销

2026-11-28 在 OrbStack 隔离候选 `44480a4c` 上验收。PC 频道页和移动个人页使用同一个测试账号，分别登录并建立独立会话。第三个浏览器上下文使用保持启用的另一账号，以便识别续期服务本身的故障。[普通 Web 验收矩阵](../features/auth-session-overnight-recovery-plan.md#修复验收)

## 账号样本与原始期限

通过本机 Gateway，以 Chromium 153 登录并读取受保护的 `User/GetUserByHttpContext`。PC 为 1920 × 1080，移动触屏模拟为 390 × 844、DPR 3。三条 `radish-web` 会话分别绑定独立授权，均位于租户 `0`，每条授权各有一条 access token 和一条 refresh token 记录。

| 浏览器样本 | 原页面 | 原短令牌到期时间（北京时间） |
| --- | --- | --- |
| 测试账号，PC | `/messages?channelId=92900` | 14:07:36 |
| 同一测试账号，移动 | `/me` | 14:07:38 |
| 启用的对照账号，PC | `/me` | 14:07:40 |

关闭业务页面，保留原浏览器上下文。14:03:25，只在一次性业务库把该租户的测试账号 `IsEnable` 设为 `false`，核实恰有一行变更且对照账号仍启用。此时两条测试会话均未标记撤销，授权仍为 `valid`，原令牌截止时间未变。Console 用户页可筛选和展示启停状态，本轮用数据库准备停用样本。[用户列表](../../Frontend/radish.console/src/pages/Users/UserList.tsx)

## 自然到期后依次重开

等三个原短令牌自然到期，先查库确认三条会话仍处于停用账号时各自的状态，再依次从原上下文打开原页面。每次重开后核对原会话、对应授权及该授权的令牌记录。

| 观测时间（北京时间） | 浏览器结果 | 本次续期后的数据库状态 |
| --- | --- | --- |
| 14:07:42，测试账号 PC | 会话状态返回 `200`，取令牌返回 `401`，进入登录表单 | PC 会话及授权已撤销，移动会话及授权仍有效 |
| 14:07:43，测试账号移动 | 会话状态返回 `200`，取令牌返回 `401`，进入登录表单 | 两条会话及对应授权均已撤销。两端均已清空加密凭据、短令牌截止、刷新租约和重试时间 |
| 14:07:44，启用的对照账号 | 取令牌返回 `200`，在 `/me` 成功读取原账号和租户 | 原会话和授权仍有效，access token 和 refresh token 各新增一条 |

两条停用账号授权下的 access token 和 refresh token 计数始终各为一。两端均未出现成功的登录回调或受保护账号读取。由此确认停用状态阻止新签发，撤销发生在各会话首次实际续期时。该候选尚未提供在停用时主动撤销该账号全部普通 Web 会话的入口。本轮关页等到期，已建立 Hub 连接的截止行为见[既有浏览器验收](./auth-session-candidate-2026-11-25.md#11-月-26-日浏览器与-hub-截止联验)。

后端及 Web 客户端、Console 构建通过，一次性 PostgreSQL 的 `dbmigrate apply` 与 `verify` 均通过。签发回归使用实际账号查询条件，覆盖授权码与刷新两条路径、其他账号和其他租户。60 项后端定向测试和 12 项前端 Web 会话测试通过。[签发回归](../../Radish.Api.Tests/Auth/WebAuthSessionTokenHandlerTest.cs)

验收后关闭三份浏览器上下文，隔离项目的 6 个容器、4 个卷及 1 个网络均已清理。五个临时镜像标签、证书和工作目录已移除，`127.0.0.1:35443` 已释放。

## Console 停用入口与主动撤销

同日从 `c50adb21` 实现停用命令，在独立的 OrbStack 候选上重新构建并执行 PostgreSQL 的 `dbmigrate apply / verify`。PC 频道页与移动触屏个人页登录同一测试账号后全部关页，另一个启用账号保留独立普通 Web 会话。操作者用第四个浏览器上下文登录 Console。[停用契约](../features/auth-session-overnight-recovery-plan.md#web-account-disable-proposal)

- **跨库失败与恢复。** 首轮页面预检在 Console 授权回跳中提前导航，清理后改为等受保护账号读取成功。随后首次提交暴露了 EF Core 批量更新的查询翻译错误。主库已停用账号，Console 显示「Web 会话待撤销」。修复查询并在原库重建 API 与 Auth 后，后台自行接管同一任务，状态为 `Succeeded`，保留一次失败计数。两条原会话和授权均已撤销，有效 refresh token 为零。
- **正常停用。** 全新样本在北京时间 15:13:52 完成提交和详情重载。Console 从用户详情填写原因后，接口返回 `200` 和 `Completed`，窄屏重载亦显示「账号已停用，Web 会话已撤销」。两个普通 Web 浏览器均仍关页。此时主库仅有一条成功任务，审计对应操作者、目标和租户。认证库中两条原会话及授权已撤销，凭据、短令牌截止与租约均已清空，有效 refresh token 为零。对照账号的会话与 Console 授权仍有效。
- **浏览器重开。** PC 和移动端从原上下文访问原页面，会话状态均为 `401`，随后进入登录表单，均无取令牌请求、成功回调或受保护身份读取。15:18:48，对照账号在原短令牌自然到期后取得 `200`，以同一会话轮换一次，读取到原账号和租户。两条已撤销会话在此期间未变化。
- **并发和事务。** SQLite 及隔离 PostgreSQL 都通过三组数据库定向回归，覆盖同账号跨连接的登录挂接与撤销、重复提交、主库审计写入失败回滚、认证库撤销中断回滚及幂等重试。另验待激活会话、已撤销但有残留授权的会话、跨租户目标、受保护账号、其他用户及其他客户端授权。[主库用例](../../Radish.Api.Tests/Repositories/UserRepositoryTest.cs) · [撤销用例](../../Radish.Api.Tests/Auth/WebAccountSessionRevocationTest.cs) · [并发用例](../../Radish.Api.Tests/Auth/WebAccountSessionConcurrencyTest.cs)

验收后关闭浏览器，清理 6 个容器、4 个卷、1 个网络和 5 个候选镜像标签，确认仅本次使用的 `127.0.0.1:35443` 已释放。
