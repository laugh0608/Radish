# F4-R R2-P03 商品评价与公开等级范围审计

> 日期：2026-08-09（Asia/Shanghai）
>
> 状态：代码事实核对与推荐方案已完成，等待用户确认
>
> 范围：只读审计商品、订单、公开资料、经验等级与内容治理边界；未修改正式代码、API、数据库、权限、迁移或运行时行为，未启动服务或浏览器

## 1. 触发原因

R2-P03 设计反馈提出两项超出现有公开详情能力的产品增量：

1. 公开主页显示用户等级；
2. 商品详情显示五星综合评分与购买用户评论，并允许已购用户评分。

两项都不能只靠前端展示完成。等级当前没有进入公开资料投影；商品评价当前没有实体、读取 / 写入 API、购买资格校验、聚合或单条评价治理目标。继续直接修改正式 UI 会形成无法由服务端证明的假能力，因此先形成本记录并等待范围确认。

## 2. 当前代码事实

### 2.1 商品与订单

- `Product / ProductVo` 已提供封面、图标、价格、库存、已售、限购、有效期、上架与版本信息，没有评分、评价数量或评价摘要字段。
- `ShopController / ProductService` 已提供匿名商品列表 / 详情、登录购买资格检查、购买与订单能力，没有商品评价读取、本人评价或评价写入入口。
- `Order` 位于 Main 存储，包含 `TenantId / UserId / ProductId / Status / CompletedTime`，足以权威证明用户是否完成过该商品订单。
- `OrderStatus.Completed` 表示履约已完成；Pending、Paid、Cancelled、Refunded 与 Failed 都不能直接作为“已完成购买评价”资格。

### 2.2 公开资料与等级

- `UserPublicProfileVo` 只公开用户标识、显示名、公开 ID / index、创建时间、头像、装扮和宠物卡，没有等级字段或主页背景附件。
- 等级数据存在于 `UserExperienceVo`，但现有公开资料路由没有读取它；普通经验接口只允许本人，管理接口受 Console 权限保护。
- `UserExperienceVo` 同时包含总经验、进度、排名、冻结状态与冻结原因，不能把整个对象直接复用到匿名公开资料。
- 论坛评论等现有公开表面已显示等级数值，因此“只公开当前等级与等级名”与既有可见性方向一致；仍需通过专门的公开安全投影，而不是放宽经验接口。

### 2.3 治理

- 现有举报目标包含 `Product`，只能治理商品本身，不能标识一条商品评价。
- 公开文字评价若没有独立目标快照、可见性校验、软删除 / 隐藏和案件动作，就不能安全上线。
- 现有 `console.moderation.*` 权限可以继续承接评价案件，不建议为了评价新增 Console 权限种类；需要新增的是受控 `ProductReview` 治理目标，而不是新审批流。

## 3. 推荐方案

### 3.1 公开等级安全投影

- 在 `UserPublicProfileVo` 中只新增 `VoCurrentLevel` 与 `VoCurrentLevelName`；不存在经验记录时返回权威初始等级，不由前端猜测。
- 不公开总经验、升级进度、排名、冻结状态、冻结原因或管理建议；不放宽 `ExperienceController` 的本人 / Console 授权。
- 公开主页标题使用现有 `VoDisplayName ?? VoUserName` 与 `VoPublicIndex / VoPublicId` 组合为“昵称#公开ID”；不得回退展示内部 LongId。
- 当前 Pencil 背景区只使用主题生成的视觉封面，不新增用户上传主页背景、附件 ACL 或个人装修能力。

### 3.2 商品评价模型

- 新增 Main 存储实体 `ProductReview`：LongId 主键、`TenantId / ProductId / UserId / EligibleOrderId / Rating / Comment / Version`、创建 / 修改审计和软删除字段。
- 以 `(TenantId, ProductId, UserId)` 建立唯一约束：每个用户对同一商品只保留一条评价，重复购买不会重复放大综合评分。
- 评分必须为 `1..5` 的整数；评论可选，建议规范化后最多 `500` 字。创建、修改与删除均由服务端校验当前用户和租户。
- 写入资格要求存在当前租户、当前用户、当前商品的非删除 `Completed` 订单；服务端保存一条满足资格的 `EligibleOrderId` 作为“已购”证据。
- 创建使用唯一约束与事务抵抗重复提交；修改 / 删除使用 `ExpectedVersion` CAS，冲突返回结构化 `409` 并保留前端草稿。

### 3.3 公开读取与聚合

- 公共评价读取返回综合评分、评价数量、五星分布与稳定分页列表；平均分由数据库对可见评价聚合，展示到一位小数。
- 商品主资料仍独立裁决 `404 / unavailable`；评价读取失败只降级评价区，不覆盖商品主体和购买动作。
- 当前用户评价与“是否可评价”使用登录态独立读取；匿名用户可读公开评价，但不能提交。
- 真实零评价显示空态，不伪造 `5.0`、默认五星或示例评论。

建议 API 形态：

- `GET /api/v1/Shop/GetProductReviews/{productId}`：匿名，返回聚合与分页评价；
- `GET /api/v1/Shop/GetMyProductReview/{productId}`：Client 登录，返回本人评价与资格；
- `PUT /api/v1/Shop/UpsertProductReview/{productId}`：Client 登录，写入 `Rating / Comment / ExpectedVersion`；
- `DELETE /api/v1/Shop/DeleteProductReview/{reviewId}`：Client 登录，以 `ExpectedVersion` 删除本人评价。

前端继续由 `@radish/http` 承接统一结构化错误；所有 LongId 在 TypeScript 侧保持字符串，不引入 number 转换。

### 3.4 评价治理

- 新增受控 `ProductReview` 举报目标，快照包含商品、评价、作者、评分与评论正文；举报前校验评价当前公开可见。
- 继续复用现有治理案件、审计和 `console.moderation.*` 权限，不新增评价审批流或单独 Console 权限。
- 评价被治理隐藏 / 删除后必须从列表、数量、平均分和五星分布同时排除；治理写入与评价可见性继续位于 Main 存储事务边界。

## 4. 设计落点

- PC 商品页在价格 / 购买主区显示紧凑的“综合评分 + 评价数”，详情区新增五星分布与两条已购评价预览；商品页仍保持单页，不恢复与公开主页的合并画板。
- Mobile 商品页在购买动作之后、商品详情之前显示评分摘要与一条评价预览；完整评价列表按现有页面内展开 / 分页，不新建移动壳层。
- 登录且具备 Completed 订单的用户显示“去评分 / 编辑评价”；未购买、匿名、资格 unavailable 与 CAS `409` 分别表达，不把按钮 disabled 当作错误说明。
- 必要关键状态补充零评价、评价局部 unavailable、无购买资格、本人 dirty / `409` 与评价被治理隐藏，不复制完整商品路由。

## 5. 本批不扩入

- 不做商家回复、评价回复、评价点赞 / 有用、评价图片 / 视频、匿名评价、追评、标签词云、推荐排序或实时刷新。
- 不允许每个订单重复评分，不以客户端订单列表决定资格，不把 Paid / Failed / Refunded 视为 Completed。
- 不新增 Console 权限、评价审批流、动态评分维度或独立评价中心。
- 不新增用户自定义主页背景上传；当前背景区只属于共享主题视觉。
