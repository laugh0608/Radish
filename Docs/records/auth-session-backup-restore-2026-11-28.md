# 普通 Web 认证库备份恢复与重新登录验收

2026-11-28 在 OrbStack 隔离候选 `d3ff7c3e` 上通过验收。恢复登录期间的认证库备份后，先撤销回档会话，再开放续期。PC 与移动视口中已退出的两个账号均须重新输入凭据。以两端第一次登录时受保护接口 `GetUserByHttpContext` 返回的用户和租户作为比对基准。下列时刻均为北京时间。[会话验收矩阵](../features/auth-session-overnight-recovery-plan.md#修复验收)

## 备份、退出与离线撤销

| 时刻 | 操作与实测结果 |
| --- | --- |
| 13:31:55 | 从 PostgreSQL 16.15 的认证库生成 `pg_dump -Fc` 备份。库中有两条已激活的 Web 会话，两份对应授权均有效，每份授权各有一枚有效 refresh token。备份留在一次性 PostgreSQL 容器内，权限为 `0600`，归档目录可读。 |
| 13:31:56 | 两端分别点击「退出登录」。`POST /web/session/logout` 返回 `200`，OIDC 登出返回 `302`，页面回到 `/discover`，会话状态为 `401`。源库两条会话均已撤销，凭据已清空，对应授权均已撤销。保留各自退出后的浏览器上下文。 |
| 13:32:46 | Gateway、Auth 和 API 均已停止，回环 HTTPS 入口无法连接。核对归档 SHA-256 后，以 `pg_restore --single-transaction --exit-on-error` 还原到新的空认证库。复核两条会话及其授权与备份时一致，均恢复为有效，旧短令牌尚未到期。 |
| 13:32:47 | 在恢复库的一笔事务内，按 `radish-web` 登记及关联授权撤销两条会话、两份授权和两枚有效 refresh token。清空会话凭据、短令牌截止及刷新租约字段，保留原会话与授权记录。提交后复核有效 refresh token 为零，源库保留退出后的状态。 |

数据库恢复与撤销期间均核对三个服务已经停止、宿主端口空闲。API、Auth 和 DbMigrate 的连接目标切到恢复库后，`dbmigrate verify` 通过。原业务库和密钥卷持续保留。本轮演练范围为普通 Web 的认证库恢复。

## 开放续期后的两端验证

最后一枚旧短令牌在 13:36:31 自然到期。确认两枚均已过期、旧会话仍已撤销后，启动 Auth 和 API，核对两个容器实际连接恢复库，再开放 Gateway。`/web/session/status` 于 13:36:37 对匿名请求返回 `401`。

两端保留退出后的浏览器资料，分别重新访问原受保护页面。两页都出现真实的登录表单。13:36:40，在任何一端提交凭据之前，页面均未取得新令牌或受保护账号数据，恢复库中的有效 Web 会话与有效 Web 授权均为零。

| 浏览器与受保护入口 | 重新登录 | 再次重开 |
| --- | --- | --- |
| PC Chromium 153，1920 × 1080，`/messages?channelId=92900` | 13:36:42，测试账号提交一次表单，经一次回调返回原频道，频道参数保留 | 原账号与原租户，留在原频道，无额外登录 |
| 移动 Chromium 153 触屏模拟，390 × 844、DPR 3，`/me` | 13:36:43，管理账号提交一次表单，经一次回调返回个人页 | 原账号与原租户，留在个人页，无额外登录 |

两端重新登录后取令牌和受保护账号接口均返回 `200`。恢复库最终保留两条已撤销的原会话及对应授权，另有两条新会话和两份新的有效授权。新会话的用户与租户和各自基准一致，旧会话的撤销状态、版本和已清空的凭据均未变化。源认证库保留退出后的两条撤销记录。

本轮从本地源码及缓存构建五个 linux/arm64 候选镜像。初始迁移 `apply / verify`、恢复库的 `verify` 以及三个退出相关定向测试均通过。

结束后确认认证库备份文件已删除。项目容器、卷、网络分别由 6、4、1 降至零，源库和恢复库随一次性卷清理。五个候选镜像标签、临时证书和浏览器资料已清理，宿主端口 `127.0.0.1:35443` 已释放。
