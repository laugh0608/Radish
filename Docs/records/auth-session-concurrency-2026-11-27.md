# 普通 Web 会话多标签与双 Auth 联验

2026-11-27 在 OrbStack 验证普通 Web 候选 `1ca52c03`。本轮关注同一会话的多个请求争用刷新租约时，浏览器看到的页面、身份与 PostgreSQL 已提交的结果能否一致。[会话专题与验收矩阵](../features/auth-session-overnight-recovery-plan.md#修复验收)

## 环境与判定方法

- 从本地缓存构建 API、Auth、Gateway、Frontend 与 DbMigrate 五个镜像。仅发布宿主回环端口 `127.0.0.1:35443`，浏览器通过同源 HTTPS 访问 Gateway。一次性 PostgreSQL 完成 `apply` 和 `verify`。
- PC Chromium 使用 1920 × 1080 视口，移动 Chromium 使用 390 × 844 视口及触屏模拟。两端各用一套资料验证刷新，另一套资料验证退出。每套资料只交互登录一次，两个真实标签页共享 Cookie。刷新样本分别打开消息频道和个人页，退出样本使用论坛公开页观察迟到响应。
- 通过浏览器请求事件比对取令牌的状态码、当前用户接口返回的账号与租户、登录导航及页面地址。独立数据库连接观测同一会话、授权、租约的取得与释放、加密凭据是否变化，并计数已签发、已兑换及仍有效的令牌。观察记录仅保存计数与比较结果。
- 短令牌按候选配置自然到期。两页首次取令牌请求在浏览器侧等齐后一起放行。单页丢包只发生在数据库已确认写回、浏览器尚未收到上游成功响应时。

## 同一会话的两页同时恢复

| 浏览器 | 消息频道取令牌 | 个人页取令牌 | 对应会话的数据库结果 |
| --- | --- | --- | --- |
| PC | `503 → 200` | `200` | 租约取得一次、写回一次 |
| 移动 | `200` | `503 → 200` | 租约取得一次、写回一次 |

两端的消息页均留在原频道，个人页均留在 `/me`。四个页面均通过当前用户接口确认原账号及租户，期间无登录导航。每条会话沿用原授权，版本由 2 变为 4，只新增一组令牌，刷新令牌一枚已兑换、一枚有效。

## 一页丢包，另一页正常接收

继续使用上述两套资料，等上一组签发的短令牌再次自然到期。同时放行两页的首次请求，只丢弃消息页的首个上游 `200`。从丢弃响应到页面收到下一个 `200` 的时间如下。

| 浏览器 | 消息页观察到的顺序 | 丢包后自动恢复 | 同一资料的个人页 |
| --- | --- | ---: | --- |
| PC | 连接重置、`200` | 14.7 秒 | `503 → 200` |
| 移动 | `503`、连接重置、`200` | 29.9 秒 | `200` |

四个页面都恢复原身份、保留各自的原地址，全程没有登录导航。每条会话仍只新增一组令牌，版本由 4 变为 6，观察到一次租约取得和一次成功写回。移动消息页经历连续两次临时失败后也能自行恢复。

## 主动退出与迟到的成功响应

在两端各自的论坛页暂停一条已写回的刷新响应。随后从同一资料的个人页点击「退出登录」，确认 PostgreSQL 已撤销原会话与授权，且论坛页实际收到退出广播，再向论坛页交付刚才暂停的 `200`。

PC 和移动端结果一致。退出页回到 `/discover`，论坛页收到迟到的成功响应后仍留在公开页，保持退出状态。两页重新读取会话状态均为 `401`。每条样本的写入顺序均为取得租约、写回轮换、撤销，最终租约已释放、加密凭据已清空。

## 双 Auth 接管

两个 Auth 使用相同镜像、同一 PostgreSQL 和持久密钥卷。网关只指向 B 并停止 A 后，PC 和移动端沿用原资料打开个人页，各自取令牌成功并通过当前用户接口确认原身份。B 处理了两次取令牌，A 为零。两条会话均直接复用已有凭据，租约记录和令牌计数保持一致。

一次性 DbMigrate 已在迁移后移除，Compose 首次尝试启动已停的 A 时报告缺少依赖。复核容器的项目与服务标签后启动原容器。两端重开相同浏览器资料均无需交互登录，原会话的加密凭据保持一致。

网关恢复 A、B 轮询后，在每套资料中分别同时放行消息页和个人页请求。两轮实测，A 各执行两次取令牌，B 各执行一次。两端的个人页均直接收到 `200`，消息页均为 `503 → 200`。数据库观察到的持有者均为 B，每条会话只取得一次租约、写回一次，版本由 6 变为 8，四个页面均恢复原身份。实例命中数取自各进程完成的控制器调用，写入归属取自 PostgreSQL 连接的应用名。

### 签发成功、会话写回中断

仅在一次性库中对两条刷新样本阻断轮换写回。20:33:07 两条会话均由 A 取得租约。20:33:08 签发记录各增加一组，旧凭据已兑换，会话行仍保留原加密版本。此时停止 A，让网关只向 B 转发，解除样本的写入故障。

PC 消息页先收到网关切换期间的 `502`，再收到 `503`，约 44 秒后收到 `401`。两条样本的数据库记录一致。B 在租约到期后各取得一次租约，旧凭据已失效，库中没有可用的新版本。20:33:52 两条会话和对应授权均已撤销，剩余有效刷新令牌均为零。中断之后没有第二次签发，也没有成功的会话写回。A 随后重启，B 在整个接管期间持续运行。

### 两页同时转入交互登录

此项未通过。两套浏览器资料各有两个受保护页面。失效后，Auth 收到四次开始登录请求。随后四次授权请求中，两次进入账号登录页，两次在授权端点返回 `400`。PC 两页未能同时显示登录表单。验收脚本在 PC 断言处结束，移动端两个标签各自的最终页面未独立记录。之后用原资料分别单开 PC 消息页和移动个人页，两端均先收到会话状态 `401`，再正常显示登录表单。

Auth 每次开始登录都把该流程的关联值写入同名 Cookie。授权时使用当前 Cookie 与当前流程匹配，同一浏览器并行开始登录会覆盖彼此的关联值。下一批需解决多标签并行登录关联，复验每个页面进入交互登录并能回到各自原地址。[登录入口](../../Radish.Auth/Controllers/WebSessionController.cs) · [授权入口](../../Radish.Auth/Controllers/AuthorizationController.cs)

## 自动化回归

- 前端补充跨标签退出广播到达后再交付成功刷新响应的用例，断言当前页保持退出、没有残留内存凭据、没有再次广播。普通 Web 与共享 HTTP 测试分别通过 577 和 84 项。[前端用例](../../Frontend/radish.client/tests/webSession.test.ts)
- 服务端补全写回失败后下一持有者的两种结果。租约有效时返回临时失败且不再次兑换，租约到期时，签发方仍接受旧凭据便恢复原会话，明确拒绝则清除凭据并撤销授权。持久化定向用例 20 项全部通过。扩展到 Web 会话相关测试后，宿主通过 81 项，3 项需要独立 PostgreSQL 管理连接的迁移测试按条件跳过。本轮隔离 Compose 的迁移已实际执行。[服务端用例](../../Radish.Api.Tests/Auth/WebSessionPersistenceTest.cs)

## 并行登录修复候选

`67c1baad` 将每次登录的浏览器关联凭据独立命名。定向测试覆盖两条待登录流程交错完成、各自选择关联凭据、账号与租户校验、回调只清理本流程，以及固定名称旧流程的兼容。Gateway 用例同时检查 Auth 登录端点、普通会话端点、令牌端点和其他上游。控制器与持久化测试 40 项通过，含这些用例的扩展认证回归共 110 项通过。PC 和移动端两组双标签交互登录回流待实测。[转发与回调测试](../../Radish.Api.Tests/Auth/WebSessionControllerTest.cs) · [持久化绑定测试](../../Radish.Api.Tests/Auth/WebSessionPersistenceTest.cs)
