## 1. 结论

- `R2-P03` 保持 R2：Docs 详情、商品详情、公开主页与 Legal 继续继承 `R1-P02 / R1-F01` 的 Public Header、连续阅读面、状态语法与 Client 胶囊导航，只补只读详情之间的结构、动作和 mobile 顺序差异，不复制四个完整路由。
- PC 顶部导航不再拉伸早期 `1120 × 80` Header 组件，而是直接继承 R1-P02 正式 Client 的 `1440 × 68` 完整结构：品牌、发现 / 论坛 / 聊天 / 更多、全局搜索、发布、通知和账户入口保持一致。
- PC 长内容固定为“目录 / 章节导航—连续正文—来源与法务锚点”三段结构；Docs 与 Legal 共用同一阅读语法，标题、原文语言、更新时间、章节锚点和来源信息先于长文辅助动作。
- PC 商品与公开主页已拆成两个独立顶层画板：商品页使用展示图—价格 / 约束 / 综合评分—购买动作—评价预览—详情 / 服务边界；公开主页使用背景封面—身份 / 公开等级 / 统计 / 关系动作—公开内容 / 资料。
- 三张 PC 主区统一为 `24px` 横向外边距、`12px` 核心分栏，主要卡片内距收敛到 `14–20px`；正文主轴按释放空间自适应展开，不再保留 `32 / 51px` 外围和 `16 / 24px` 卡间大缝隙。
- Mobile `390 × 844` 使用三个独立顶层页面，不使用外部说明板、设备卡片或多页面合并容器：Legal 先标题 / 原文元数据 / 章节锚点再长文；商品固定为顶部大幅商品图、价格 / 标题 / 约束、购买动作、评价摘要 / 预览、详情的成熟电商顺序；公开主页先背景、昵称、`用户名#公开ID`、个性签名、公开等级与权威统计，再进入关系动作和公开内容。
- PC / Mobile 的墨蓝主动作统一使用暖白图标和文字，购买与发消息不再出现深底深字的低对比组合。
- PC / Mobile 商品价格统一使用清晰可辨的 `carrot` 萝卜轮廓表达品牌萝卜币，不使用 `¥` 等真实法币符号或近似小草的 `sprout`，数值、币种名称和现有购买契约保持不变。
- 商品举报继续复用现有 `Product` 治理入口；公开主页主资料、统计、关系与内容按既有权威状态独立裁决，不用占位零值或装饰性数字掩盖未读取结果。

## 3. 信息与动作层级

### 3.1 长内容

- 文档标题、类型、更新时间、预计阅读时长和原文语言属于正文元数据，不放入外部说明卡。
- PC 目录用于同页定位，正文保持连续阅读；来源、转载 / 法务说明和版本信息收在右侧弱辅助区，不挤占正文主轴。
- Mobile 用章节锚点承接 PC 目录，先让读者确认当前文档与章节，再进入长文；导航和元数据不与正文合并成展示画板。

### 3.2 商品

- 价格、库存、限购、有效期、已售等购买判断信息与购买主动作置于首个动作区；确认提示明确购买仍服从既有幂等 / CAS 与服务端裁决。
- PC 与 Mobile 均使用 Pencil 生成并随设计源保存的商品展示图；Mobile 先图后信息，返回 / 分享使用图片上方的轻量悬浮动作，不用文字工具栏挤占首屏。
- 举报与分享保持真实可用，但视觉层级低于购买；商品 unavailable 时只禁用购买，不把合法的举报入口一并隐藏。
- 综合评分在价格 / 购买判断区使用一位小数与已购评价数，详情区再展开五星分布；零评价显示真实空态，不展示默认 `5.0`。
- 登录且有 Completed 订单的用户显示“去评分 / 编辑评价”，未购买原因直接说明；Mobile 的评价区位于购买动作之后、商品详情之前，不形成独立移动壳层。
- 不新增购物车、优惠券、动态价格、退款流程或新的订单状态。

### 3.3 公开主页

- 主题背景和头像之后按三层建立身份：第一行显示昵称，例如“林墨”；第二行显示 `用户名#公开ID`，例如 `LinMo#10006`；第三行显示个性签名或真实空文案“这个用户什么都没有写～”。公开 ID 不得回退为内部 LongId，帖子、文档、关注、粉丝等统计只在权威结果成功后显示真实值。
- PC 头部信息卡只保留两列：左侧为一个完整身份列，首行并排昵称与 `用户名#公开ID`，下方依次为签名、等级 / 加入时间；右侧统计与关系动作共享统一右边界并上下排列。封面与信息底高度接近 `1:1`，不再拆分独立签名卡或引入第三套对齐线。
- 等级由公开资料的安全投影提供，只显示当前等级与等级名；经验、进度、排名和冻结状态不进入公开主页。
- 消息、关注、屏蔽和分享继续使用既有关系能力与版本边界；关系状态 unavailable 时失败关闭，不猜测“未关注”或继续允许写入。
- 公开内容和真实空态位于关系动作之后；未读取、无内容、权限拒绝与用户不存在保持不同语义。

## 4. 必要关键状态

- **权威 `404`**：主详情不存在时显示明确未找到与返回动作，不让次要统计或内容请求覆盖主资料裁决。
- **商品 unavailable**：购买失败关闭，保留结构化错误与重试；商品举报仍可从当前受权详情发起。
- **公开统计 unavailable**：局部显示读取失败与重试，不伪造 `0`、`—` 或粉丝数。
- **关系 unavailable**：关注 / 屏蔽状态无法确认时停止关系写入，不把未知状态渲染成可操作默认值。
- **真实空态**：已成功读取但没有公开内容时显示成功空集合，与 `404`、unavailable 和权限拒绝分离。
- **商品举报弹窗**：复用共享举报结构和既有 `Product` 目标，不新增举报原因、匿名 URL intent 或治理事务。
- **真实零评价**：已成功聚合但评价数为零时显示成功空集合，不伪造五星、均分或评论。
- **评价资格与 dirty**：无 Completed 订单时解释只读原因；编辑草稿离开前显式确认，不能用 disabled 按钮替代状态说明。
- **评价 CAS 与降级**：`409` 保留星级和评论草稿；公开评价 unavailable / stale 只降级评价区，不覆盖商品主体和购买动作。
- **治理与申诉**：被治理评价立即退出公开聚合；申诉恢复继续校验来源动作、父商品可用性与结果版本。

关键状态板使用 `$bg-app / $bg-surface / $border-soft` 与浅色 success / warning / danger 语义；错误与降级状态保留辨识度，但不使用大面积深色矩阵底。

## 5. 契约与停止线

- 商品购买、关系写入和既有举报仍保持原 API、权限、URL、LongId、幂等 / CAS、结构化错误、治理事务和存储边界；商品评价新增边界严格服从经确认的[范围审计](/records/f4-r-r2-p03-product-review-public-level-scope-audit-2026-08-09)与[能力门禁实现](/records/f4-r-r2-p03-product-review-public-level-capability-gate-implementation-2026-08-09)。
- 评价只允许 Completed 购买者按用户 / 商品唯一关系写入；公开等级只投影当前等级和等级名。Pencil 不表现任何未实现的经验详情、评价媒体或实时能力。
- 不新增权限种类、批量动作、购物车、审批流、动态商品字段、实时刷新或新的移动壳层。
- 不把公开资料统计失败提升为整页失败，也不让局部请求回写并覆盖主详情的 `404 / unavailable`。
- 本轮不进入正式视觉代码实现，不启动服务、浏览器或 Gateway smoke，不提前推进 `R2-W02 / R2-A02` 或任何 R3 页面。
