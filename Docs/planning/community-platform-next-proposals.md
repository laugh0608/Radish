## 1. 社区徽章

**用户路径。** 用户达成明确贡献后收到站内通知，在个人徽章页看授予日期、说明和可公开的来源，并选择在公开主页展示。管理员可查看规则与发放记录，手动授予、撤销并填写原因。可借鉴 Discourse 的自动与人工授予、分组和分级能力，规则和视觉统一沿 Radish 的社区语义。[Discourse 徽章说明](https://meta.discourse.org/t/understanding-and-using-badges/32540)

**当前底座。** 商城已经支持 `Badge / Title` 类型的商品权益，通过 `UserBenefit`、`UserActiveBenefit` 和 `UserAdornmentVo` 消费。建议建立社区徽章的独立定义与授予记录。个人主页可同时展示贡献徽章和已有装饰，首版论坛作者区继续使用现有装饰入口；以后若统一佩戴槽位，再评审选择、过期、撤销与旧商品兼容。购买权益、社区贡献和角色权限分别由各自业务域裁决。[商城身份权益](../features/shop-product-effect-entitlement-fulfillment.md)

| 切片 | 设计与验收 |
| --- | --- |
| 定义和记录 | 定义包含稳定键、组别、名称、说明、图标、展示控制、规则版本和启用状态。授予绑定租户、用户、定义与稳定来源键，首版每人每枚只获得一次。授予、撤销及重新授予具有独立审计历史，停用规则只停止新的自动发放。 |
| 三个规则加人工授予 | 建议首次发布公开主题、首次公开回答获采纳、首次公开 Wiki 贡献获批。由业务成功提交后的权威事实触发，使用现有可靠任务与数据库唯一约束。测试同批重复、迟到、回放、租户隔离、隐私变化和授权撤销。若现有队列租约语义影响发放，沿原专题评审。[Outbox 候选](./engineering-improvement-candidates.md#2-outbox-租约归属与迟到结果) |
| 运营和展示 | Console 管理规则启停、人工授予、用户发放历史及撤销；个人持有列表与公开主页展示各自有独立可见性。公开来源引用仅在目标当前可公开时显示。测试已有购买徽章、手动与自动同时命中及已撤销徽章隐藏。 |

待确认首批规则、展示默认值、是否按有效历史事实一次性补发，以及来源被撤回时处理哪些徽章。首版建议从上线后的事件开始，补发提供预览、批次去重和审计后再开放。规则平台先使用代码内登记的规则类型和参数，任意 SQL、自定义脚本、可重复活动徽章及信任等级联动留作独立版本。

## 2. Token 过期与隔夜恢复

已完成配置核对及正式镜像 7 分钟和 27 分钟的关页重开对照。修复边界与验收矩阵见[隔夜会话排查与验收方案](../features/auth-session-overnight-recovery-plan.md)。[隔离复现记录](../records/auth-session-overnight-default-lifetime-2026-11-21.md)

**已知事实。** Auth 默认签发 5 分钟 access token 和 25 分钟 refresh token，不活跃窗口为 7 天。期限配置缺失时，宿主使用 60 分钟和 30 天的回退值。认证站点 Cookie 另有两小时滑动期限。隔离环境中的 27 分钟组因 refresh token 到期退出。原始反馈的实例、入口和时间已无法追溯。[Auth 配置](../../Radish.Auth/appsettings.json) · [宿主配置](../../Radish.Auth/Program.cs) · [Token 不活跃规则](../guide/auth-idle-session.md)

| 切片 | 设计与验收 |
| --- | --- |
| 定位掉线 | 区分社区 Web 与 Console。在授权的隔离环境核对客户端 ID、有效期、是否发放 refresh token、关页后的存储与冷启动、浏览器后台、并发刷新、返回码和 Cookie 路径。只记录配置值、时间和错误分类，证据避开 token 原文。用受控时钟或缩短的隔离配置复现隔夜行为。 |
| 恢复普通 Web 会话 | Auth 以 `radish-web` 执行 7 天不活跃窗口、30 天绝对上限和最多 5 分钟的 access token。浏览器通过同源 Cookie 恢复，旧普通 Web 会话在开启后通过一次重新认证迁移。Flutter 和 Console 沿用原策略。 |
| 停用与故障边界 | Auth 用服务端记录计算截止，前台真实输入可更新活动，后台刷新和 Hub 重连不延期。停用主动撤销、多实例并发、短暂故障恢复与回退已在隔离候选验收。 |

普通 Web 重开后清除 `/desktop` 新凭据的问题已在 PC 与移动视口完成修复复验。同一资料内两个入口交替刷新，八次受保护读取均匹配各自原账号。正式开关保持关闭。[两入口浏览器复验](../records/auth-session-open-page-upgrade-2026-11-28.md#两入口交替刷新的浏览器复验) · [修复验收矩阵](../features/auth-session-overnight-recovery-plan.md#修复验收)

## 3. 农场 / 牧场

**产品定位。** 作为社区内可选的休闲经营模块，采用播种、等待、收获和照料的循环，独立创作 Radish 的场景、命名、作物与动物规则。先验证玩家能理解一次经营循环，复访时能看到稳定进度。入口建议从登录态的 Workbench 进入，运营配置由 Console 管理。[产品分层](../development-plan.md#产品定位与优先级)

| 切片 | 玩家体验与范围 | 验收 |
| --- | --- | --- |
| 农场试跑 | 初始给地块和明确的起始种子，支持播种、查看预计成熟时间、收获入仓和领取下一轮必需种子。首版种子、作物和兑换使用玩法内库存 | 收获可开下一轮，从零库存有可恢复路径。重复领取、两个设备同时收获和写入失败时，各批产物只入仓一次 |
| 牧场接入 | 先做一类动物和一个栏位，农场产物可用作饲料。支持放入栏舍、喂养、等待出产和领取产物。首版采用显式喂养触发单次产出，离线期间不无限结算 | 饲料扣除、产出和仓储并发一致；跨过成熟时间、断网重试、规则变更和仓库上限均有确定行为 |
| 社交与活动 | 验证基本玩法后，再评审好友访问、帮忙和季节任务。双方可见性与互动沿既有屏蔽和租户边界 | 无许可用户无法访问私有状态或操作他人产物，限额、重复协助与撤销许可可核对 |

**服务端约束。** Main 维护地块、栏位、玩法库存和动作流水。开始生产时冻结配方版本和 `ReadyAtUtc`，服务端按 UTC 判断成熟，读取和动作可按该时刻演进，无需每株作物注册后台任务。使用行版本或等价条件更新，扣除和发放在同一事务，重复操作按稳定操作键回读。保留玩法独立产消记录与数据清理规则。

首版建议独立于萝卜币、经验、商城和现有宠物成长，便于验证可玩性和配置回滚。待确认入口、首批循环时长和产物消耗，再决定好友互助、排名、活动奖励或商城联动。涉及抢取他人产物、付费加速与跨玩法兑换时单独评审参与公平、资产幂等和滥用影响。

## 4. 第三方 API Key 鉴权与 Console 策略

**现状和边界。** Console `/applications` 已维护 OpenIddict 应用、授权类型、Scope 和 Client Secret，Auth 已配置允许 `client_credentials`。计划新增适合服务到服务集成的 API Key 策略，独立验证机器主体端到端的权限。应用仍沿现有治理入口，API Key 只是该应用的另一种凭据。首版由实例管理员授予，开发者自助、应用审核、SDK 和 Webhook 排在后续。[开放平台现状](../features/open-platform.md)

| 切片 | 设计与验收 |
| --- | --- |
| 应用授权 | Console 应用详情提供 API Key 分区，列出受支持的用途、Scope、密钥状态、过期及最近使用。新增权限分别约束查看、签发 / 轮换、撤销和授予策略。应用停用或撤销授权后，所属密钥有效权限随之收敛；状态变更与操作者可审计。 |
| 密钥生命周期 | 一次性返回高熵秘密，仅持久化可查询标识和不可逆验证值，服务器密钥版本由现有安全配置管理。支持显式有效期、限时新旧重叠和单条撤销。仅通过 HTTPS 请求头传递，错误、日志、追踪、导出和详情仅留安全标识。验证重试、并发轮换、时钟边界及多实例撤销生效时间。 |
| 权限执行 | 为专门登记的集成 API 配置机器认证方案。有效权限取实例、应用授予、密钥范围、端点策略及资源租户的交集，API 是最终业务裁决点；Gateway 承担入口隔离和频率控制。首版只开放验证过的低风险只读资源，例如公开文档列表和已发布帖子检索。401、403、429 与查询故障具有稳定、安全的响应。 |

集成主体不能冒充社区用户，用户委托访问单独走 OAuth 授权，资产、私域数据、写操作及 Console 管理动作逐项另审。部署首版需明确限流按应用还是按密钥、授权来源、失效生效时间、统计留存和紧急撤销流程。验收覆盖密钥错误、过期、跨实例 / 跨租户、超范围、轮换重叠、应用停用和日志秘密扫描。待确认首家集成方及其一条真实用例，以此冻结最小 API 清单。[OWASP REST 安全实践](https://cheatsheetseries.owasp.org/cheatsheets/REST_Security_Cheat_Sheet.html#api-keys)

## 5. 插件系统

**现状和首版切入点。** [现有程序集扫描](../../Radish.Common/CoreTool/RuntimeExtension.cs)服务于项目程序集识别，没有插件兼容契约、部署生命周期或独立信任边界。建议以一个可部署、可停用的受信扩展试点验证规则，例如为 Console 增加一项只读运营摘要导出。待确定首个实际插件再冻结接口。社区徽章和农场可以独立交付。

| 切片 | 设计与验收 |
| --- | --- |
| 扩展契约 | 由宿主定义一个版本化扩展点、输入输出 DTO、错误语义、权限和资源上限。Manifest 登记插件 ID、版本、宿主兼容范围、摘要、依赖、配置 schema 和扩展点。Console 可见插件来源、有效状态和失败原因。版本不兼容、身份重复或配置错误须有明确结果。 |
| 部署与生命周期 | 首版插件随已审核的部署产物提供，实例管理员在预先允许的清单中配置启停，重启重读配置。区分期望状态和实际生效状态，安装包、配置和升级历史可追溯。初始化出错时内建功能可运行，单插件失败可隔离到该扩展点；在受信进程内测试异常隔离与回滚，不对进程崩溃给出隔离承诺。 |
| 进程外第三方扩展 | 若要运行非信任作者的代码，独立评审操作系统或容器隔离、受限身份、网络、文件系统、资源限额、签名验证和快速停用。扩展通过窄 RPC 或已授权公开 API 访问业务能力；评审调用超时、密钥撤销、租户隔离和故障降级后再对外开放。 |

同进程装载视同授予宿主代码权限，程序集隔离只解决依赖冲突。首版不向浏览器直发插件脚本，不让插件自行写宿主表或执行任意 migration。若扩展需要业务写入，通过明确授权的宿主 Service 接口提供，插件数据的版本、备份和停用后保留分别确认。评审决定首个扩展点、受信发行者、启停语义和多实例一致性要求。[.NET 插件与信任边界](https://learn.microsoft.com/en-us/dotnet/core/tutorials/creating-app-with-plugin-support)

## 6. 软删除 `IsDeleted` 查询效率

**当前边界。** [通用 Repository](../../Radish.Repository/Base/BaseRepository.cs)按实体能力附加租户范围与 `IsDeleted = false`，部分路径允许明确包含已删除数据。帖子列表、通知分组和互动表已有包含 `IsDeleted` 的组合索引；布尔条件开销、实际筛选能力、排序和分页代价需要看生成 SQL、数据分布及执行计划。默认本地为 SQLite，部署主要为 PostgreSQL，两边分别验证。[数据库总览](../guide/database-overview.md)

| 切片 | 执行与验收 |
| --- | --- |
| 先找热点 | 从帖子分页、通知收件箱或评论分页挑 2–3 条代表查询，保留实际 SQL 形状和绑定方式。合成代表行数、租户分布、活跃比例及排序游标，包含高 / 低软删比例。PostgreSQL 看 `EXPLAIN (ANALYZE, BUFFERS)`，SQLite 看 `EXPLAIN QUERY PLAN`，分别记录取行量、读块、排序、耗时分布及写入成本。 |
| 小批调整 | 对照现有组合索引、以租户和业务键为前缀的分页索引、仅有效行的部分索引。部分索引需要实际查询谓词可被规划器识别。确认 SqlSugar 常量 / 参数、PostgreSQL prepared plan、SQLite 实际谓词语法，再决定采用哪种索引。若主要成本是排序、宽行或 join，按证据改对应路径。 |
| 审计与上线 | 对照前后分页顺序、普通读、管理端包含已删、跨租户隔离、软删、恢复和唯一约束。只给确定有收益的索引新增 DbMigrate 前滚 migration，覆盖旧库升级、重复 apply、verify 和恢复。当前部署与 migration 采用停写与事务；若需要 PostgreSQL 并发建索引，单独评审事务外执行与失败后的无效索引处置。 |

优先看正常分布下的热点 P95 和扫描行数降幅，同时核对写入、删除 / 恢复、索引体积、迁移锁等待。基线出来后再冻结验收阈值与首批查询。历史归档或硬删除牵涉引用、恢复和留存标准，独立评审。[PostgreSQL 16 部分索引](https://www.postgresql.org/docs/16/indexes-partial.html) · [PostgreSQL 16 建索引](https://www.postgresql.org/docs/16/sql-createindex.html) · [SQLite 部分索引](https://www.sqlite.org/partialindex.html) · [Radish 数据库迁移口径](../guide/database-schema-change-governance.md)
